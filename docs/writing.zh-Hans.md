# 写作规范

[English](writing.md) | 简体中文

> 对应英文版：2026-09-28。英文版更新后本页可能滞后。

本仓库文档的写法。目标是：一个懂一点 JavaScript 的读者，第一次读就能看懂每一页。

## 示例 README 的结构

每份示例 README 都按同样的顺序使用这些小节：

```markdown
# <读者会用来搜索的名字>

[English](README.md) | 简体中文

> 对应英文版：YYYY-MM-DD。英文版更新后本页可能滞后。

<一句话：读者会看到什么，或者会理解什么。>

## 试一试

<最多三条命令，然后写应该看到什么。>

## 原理

<用大白话讲清思路，并说明先读哪个文件。>

## 过去与现在

<以前怎么做，现在用什么、从什么时候开始变的，并附上官方来源链接。>

## 刻意省略

<这个小版本故意没做哪些事。>

## 验证与来源

<由哪个测试覆盖，思路来自哪里，以及许可。>
```

英文版对应的小节名是 Try it、How it works、Then and now、Limits 和 Checks and credits。

## 十条规则

1. **先写读者能得到什么。** “等一连串调用停下来之后，只执行一次”，好过“一个有边界的防抖契约”。
2. **术语第一次出现时就解释**，用一个短句即可。
3. **每个说法都要能观察到。** 写清楚读者运行之后会看到什么。
4. **写给读者，而不是写给维护者或 agent。** 像“保留来源链接”这样的指示，应该写进 [CONTRIBUTING.md](../CONTRIBUTING.md) 或 [AGENTS.md](../AGENTS.md)。
5. **多用短句和常用词。** 避免“简单地”“只需”“显然”“轻而易举”：卡住的读者看到这些词只会更难受。
6. **会过时的内容要写日期。** 写“截至 2026-09”，而不是“最新”或“现代”。
7. **只写测量过的数字**，比如行数或测试数量，代码改了就同步更新。
8. **历史和版本类说法要链接官方来源**：发布说明、MDN，或者项目自己的博客。
9. **代码保持英文并用代码格式**：命令、文件名、API 和标识符。
10. **中文镜像用自然的中文承载同样的事实**，不新增内容，并以同步行开头：`> 对应英文版：YYYY-MM-DD。英文版更新后本页可能滞后。`

## 要避开的说法

| 不要写                         | 改成                                            |
| ------------------------------ | ----------------------------------------------- |
| “contract”“mechanism contract” | what it promises，或 what the tests check       |
| “owner source”“owns the index” | the file that defines it，或 where it is listed |
| “bounded teaching example”     | small example                                   |
| 把 “boundary” 当填充词         | 直接写清楚省略了什么                            |
| 合同（机制合同、验证合同）     | 保证、约定，或直接说测试检查了什么              |
| 前沿节流                       | 节流（第一次调用立即执行）                      |

## 标题

用读者会去搜索的名字：“节流”“手写前端路由”“抽奖转盘”。README 的标题必须和 `docs/catalog.json` 里的标题一致，因为学习路线、分区索引和在线演示页都是根据它生成的。
