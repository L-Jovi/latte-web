# 检查覆盖了什么

[English](verification.md) | 简体中文

> 对应英文版：2026-10-03。英文版更新后本页可能滞后。

**历史笔记**以外的每个示例都会被自动检查。本页列出每项检查能证明什么，以及不能证明什么。

检查在 Node 24 和 npm 11 上运行，环境是 macOS（Apple 芯片）和 GitHub Actions 的 Ubuntu 24.04。示例清单来自 `docs/catalog.json`，所以任何示例都不可能只加进来、却不被检查。

| 命令                                         | 能证明什么                                                                                                                                                                                                                                                                                                                     |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `npm run check`                              | 类型检查、全部构建、手写机制、Promises/A+ 测试集、被真实使用方加载的打包库、组件行为、连着真实数据库和实时更新的 GraphQL API，以及所有文档链接。                                                                                                                                                                               |
| `npm run test:browser`                       | 每个示例页面都能无报错地打开，外加 Todo 应用、路由、富文本、网络、离线和视觉交互。每个页面一次只显示一种语言：分别以英文和中文打开，每次切换语言之后再查一遍。每个说明面板都会用两种语言逐步走一遍。每个页面在 320 像素宽的手机上都放得下，两种语言、说明面板的每一步都是如此。每项测试都在 Chromium、Firefox、WebKit 中运行。 |
| `npm run build:wasm` / `npm run test:wasm`   | 运行 Rust 测试，编译 WebAssembly 模块，并在三种浏览器中调用它。只有这个示例需要 Rust。                                                                                                                                                                                                                                         |
| GitHub 上的 `verify`                         | 汇总上面三个 job。任何一个失败、被取消或被跳过，PR 都不能合入。                                                                                                                                                                                                                                                                |
| `npm run build:pages` / `npm run test:pages` | 用首页和 `docs/catalog.json` 里列出的页面组装 GitHub Pages 站点，不放其他页面。然后在 Chromium 中、`/latte-web/` 路径下，每个在线演示都必须无报错地打开。Pages 工作流在每次部署前运行这一步。                                                                                                                                  |

## 检查不能证明什么

- **小版本是故意做小的。** React 风格的渲染器会重建组件的 DOM，而不是和上一版逐一比较，所以嵌套组件的状态和焦点可能丢失；它没有实现 React 的协调（reconciliation）算法。最简单的那个 Promise 只是教学用的状态机，只有 `promise-a+.js` 需要通过完整的测试集。
- **Draft.js 已经不再维护。** 它的示例只保证经过测试的部分：输入、加粗和保存为 JSON。
- **部分输入是模拟的。** 鼠标、指针和键盘操作使用浏览器的真实输入，但触摸手势是合成的。用输入法打字（比如中文）以及在真实手机上的操作，仍需人工检查。
- **语言检查看的是字符，不是意思。** 英文页面上只要出现一个汉字就算失败；中文页面上，代码和示例输出之外只要连续出现三个英文单词就算失败。它判断不了翻译对不对，也只看得到测试走到的状态：每个页面刚打开时和切换语言之后，以及说明面板的每一步。为了证明这项检查真的会失败，测试还会在首页埋一句另一种语言的句子，并要求检查把它报出来。
- **手机是按宽度模拟的。** `tests/browser/phone.spec.js` 把每个页面按 320 像素宽排版，两种语言都测，并把说明面板逐步走一遍。页面不能横向滚动，底部的说明面板必须一直在屏幕上，每一步标出的那部分演示必须显示在面板上方。每个页面都有[视口标签](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/meta/name/viewport)，所以真实手机也会按同样的宽度排版。测试既不用触摸输入，也不用手机自带的浏览器，所以仍需要在真实手机上人工检查。2026-10-03 之前，有 40 个页面没有视口标签：手机会按 980 像素宽给它们排版，再缩小到屏幕宽度。
- **WebKit 的离线测试**是真的把服务器停掉，而不是用 Playwright 的离线开关，因为后者有一个已知的 [Playwright 问题](https://github.com/microsoft/playwright/issues/42775)。另有一个没有 Service Worker 的对照页面，它必须重新加载失败。Chromium 和 Firefox 还会用离线开关来测试连接状态提示。
- **Core Web Vitals 取决于浏览器和这次访问。** 缺失的指标显示为“不可用”或“等待中”，绝不会显示成 0。测试证明的是测量代码能正常工作；它不是性能基准，也不复现历史上的测量结果。
- **GraphQL 应用是本地教学服务**，使用虚构账号，分页有上限，事件保存在内存里。它没有找回密码、限流、持久订阅，也没有生产环境部署。
- **外部网站的链接**不在检查范围内，一些老网站可能已经消失。

有两点只和维护者有关。Prisma 固定的间接依赖修复写在[服务端 README](../examples/graphql/server/README.zh-Hans.md) 里；安装时遵循根目录的 `allowScripts` 白名单，并且不关闭 peer 依赖检查。在沙箱里运行时，Storybook 可能打印一条关于其用户设置文件的 `EPERM` 警告。这不影响构建：构建成功与否和组件故事能否渲染另有检查，Storybook 的遥测也已关闭。

## 发布与历史

没有版本发布，也没有 npm 包。在线演示会在 CI 通过后从 `main` 部署到 GitHub Pages，只发布首页和 `docs/catalog.json` 里列出的页面。退役的文件可以从[迁移清单](migration.zh-Hans.md)链接的固定提交中找回。因隐私或版权原因撤下的内容，也已从 Git 历史中删除。
